The k6 load testing tool is written in the Go programming language. To understand how k6 behaves I first had to create the k6 binary, which is done by building the repository with the Go toolchain.

The following command, run from the repository root, compiles the source code into an executable named `k6`:

```bash
go build -o k6 .
```

This command invokes the Go compiler, which reads the `main` package (located in the root `main.go` file) and its dependencies to produce a binary file.

A JavaScript test file named `simple_test.js` was created to serve as a test. This script imports the `http` module from k6 and defines a function that executes a single GET request. It also defines a `handleSummary()` function that writes the aggregated results to a `summary.json` file and renders the console summary through the `textSummary` helper from the jslib utility library:

```javascript
import http from 'k6/http';
import { textSummary } from 'https://jslib.k6.io/k6-summary/0.0.1/index.js';

export default function () {
  http.get('https://test.k6.io');
}

export function handleSummary(data) {
  return {
    'summary.json': JSON.stringify(data),
    'stdout': textSummary(data, { indent: ' ', enableColors: false }),
  };
}
```

The built binary `k6` executed the script using the `run` command. Flags were added to generate JSON and CSV reports, and the script itself included the `handleSummary` function to generate a custom summary file:

```bash
./k6 run simple_test.js --out json=results.json --out csv=results.csv
```

Metrics and Reporting:

k6 reports several key metrics that summarize network performance and test execution. The output is represented by `data_received` (13 kB) and `data_sent` (1.1 kB), which show the volume of data transferred during the test. Latency and timing are captured through metrics such as `http_req_duration`, which indicates the total time for the request (avg 56.25ms). Other timing metrics include `http_req_blocked`, which tracks time spent blocked before sending, and `http_req_connecting`, which measures the time to establish the TCP connection. HTTPS was used, which is visible in `http_req_tls_handshaking` (avg 56.8ms), while `http_req_waiting` measures the time waiting for the first byte of the response (TTFB).

Workload volume is tracked by counts such as `http_reqs` (2) and `iterations` (1). The single `http.get()` to https://test.k6.io received a 302 redirect that k6 followed automatically, which is why one iteration produced two HTTP requests. The number of virtual users is configured in the test options or command line (1 VU in this case).

Units and Protocols:

Time values are reported in milliseconds (`ms`), microseconds (`µs`), and seconds (`s`). Data volumes are reported in kilobytes (`kB`); k6 scales these units automatically (bytes `B`, `kB`, `MB`) depending on magnitude. The requests were made over HTTPS: the TLS handshake shows up in the `http_req_tls_handshaking` metric, the negotiated TLS version is reported as `tls1.3`, and the server spoke HTTP/2.0 (the `proto` tag in the detailed outputs).

Output Files and Artifacts:

Based on the execution flags and script configuration, three distinct output files were created. The first is `results.json`, a line-delimited JSON file containing detailed metrics for every data point collected. Its format is JSON Lines (NDJSON): each line is either a metric declaration (`"type":"Metric"`) or an individual sample (`"type":"Point"`) with fields for the metric name, type, and a data object holding time, value, and tags.

A sample `Point` entry from `results.json` (pretty-printed):

The tool did not require any environment variables or external configuration files. The JavaScript file `simple_test.js` was accepted as-is without requiring a project file. Note that k6 validates JavaScript syntax and module imports, but does not require any special project structure or configuration files beyond the test script itself. After the run, the temporary artifacts (`simple_test.js`, the built `k6` binary, `results.json`, `results.csv`, and `summary.json`) were deleted so the repository was left unchanged.
